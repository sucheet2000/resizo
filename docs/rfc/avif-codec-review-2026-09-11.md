# AVIF codec review — 2026-09-11 (lead, before any code)

Builds on docs/rfc/avif.md (2026-09-09 research, same machine). Every licence and version below was re-read from the primary source today (files under scratchpad avif/licences/, verifiedAt 2026-09-11T03:56Z); every number marked (bench) comes from the 2026-09-11 Node matrix under avif/bench/, and every browser fact from the three-engine probe under avif/probe/.

## Existing codec infrastructure (inspected)
- Loader: lib/image-client/codecs.js — `once(key, factory)` memoises one `import()` + `init()` per codec per worker; `locateFile` maps to `/wasm/<name>`; `resetCodecs()` for tests. Codecs: @jsquash/jpeg 1.6.0, @jsquash/png 3.1.1, @jsquash/webp 1.5.0, @jsquash/resize 2.1.1 (all Apache-2.0, Squoosh-derived), libheif-js 1.19.8 (LGPL-3.0, HEIC decode only, base64-inlined bundle).
- Decode: lib/image-client/decode.js — every non-HEIC format goes to `createImageBitmap(blob, { imageOrientation: 'from-image' })` first (native), with @jsquash WASM decoders as the fallback per format; HEIC goes to libheif. `WASM_DECODERS` has no `avif` key, so an old browser gets "This browser cannot open AVIF images." Native decode applies EXIF/irot itself; only the WASM route runs applyOrientation.
- Encode: lib/image-client/encode.js — ENCODERS table (jpeg: MozJPEG q; webp: libwebp q or target size); `avif` throws "AVIF is not supported in the browser build yet." (the backstop against PNG bytes under an image/avif type). BROWSER_OUTPUT_FORMATS = ALLOWED_OUTPUT_FORMATS = ['jpeg','png','webp']; QUALITY_FORMATS = ['jpeg','webp'].
- Sniffer: lib/image/magic-bytes.js already returns 'avif' for ftyp major brands avif/avis (before HEIC's brands). Labels/MIME/extension for avif already exist in lib/format/upload-helpers.js and lib/image/filename.js (per the RFC; to be confirmed by the map).
- Gate: lib/image-client/capability.js — BYTES_PER_PIXEL 4, WASM_BASELINE_BYTES 24 MB, tab budget 192 MB–1 GB, IOS_BUDGET_MULTIPLIER 0.6, OPERATION_PROFILES (decode/resize/compress/convert/…); no per-format multiplier exists today.
- Architecture rule 4: `@jsquash/*`, libheif-js, jszip, pdf-lib only behind `import()` anywhere in lib/ (tests/architecture/boundaries.test.js already matches any `@jsquash/` specifier).
- CSP: script-src includes 'wasm-unsafe-eval'; connect-src 'self' (fetching /wasm/*.wasm is same-origin). No COOP/COEP → no SharedArrayBuffer → single-threaded WASM only.
- Worker: operations run in lib/image-client's worker; the batch and single-file paths share it.

## Decision (subject to the bench numbers)
- **Decode: browser-native `createImageBitmap`, no WASM decoder shipped.** Zero bytes, the fastest path, alpha and 10-bit proven in all three engines today. A browser without native AVIF (Safari ≤16.0 on macOS Monterey, old WebViews) is refused at intake by a memoised tiny-AVIF capability probe behind capability.js, with a sentence — not handed 267 KB of WASM that decodes 34× slower and costs 37 MB/MP.
- **Encode: `@jsquash/avif` 2.1.1, single-threaded build, loaded only when AVIF output is chosen and a job runs**, at a fixed speed chosen from the bench (expected 9: the only phone-tolerable setting; 8 is dominated; 6 takes minutes on a phone), quality 1–100 mapped straight to libavif's quality with the copy saying scales are codec-specific, `qualityAlpha` following quality, subsample per bench, 8-bit input only, lossless not exposed in v1. An AVIF-specific encode cost in capability.js from the measured MB/MP. Output verified independently before it is reported: the ISOBMFF header (ftyp brand, ispe dimensions, alpha auxiliary item) must match the request and the bytes must decode natively.
- **Licence duty:** ship `public/wasm/THIRD-PARTY-NOTICES-avif.txt` (or docs/licenses) carrying Apache-2.0 (jSquash/Squoosh), libavif BSD-2-Clause, libaom BSD-2-Clause and the AOM Patent License 1.0 in full, because §1.2.1 requires the patent licence to travel with a binary Implementation and the npm tarball ships only the Apache text. Nothing is copyleft; nothing conflicts with the repo's MIT licence or commercial use.
- Not built: animation (refused by brand/`moov` detection with a sentence), HDR preservation (native decode normalises to SDR 8-bit; documented), ICC preservation (converted to sRGB on decode; documented), metadata writing (none; documented), the MT encoder (needs COOP/COEP site-wide), a WASM decoder fallback.

## Bench, 2026-09-11 (Node v20, M1 Pro; scratchpad avif/bench/results.md and results.json; sharp is the reference decoder)
- Encoder: avif_enc.wasm 3,485,872 B raw / 842,416 B brotli; init ≈ 35 ms (lazy compile) incl. the first 16×16 encode; decoder module (NOT shipped) 1,170,930 B / 267,341 B.
- Speed (single-threaded, q50 / q75): 0.31 MP 36 / 53 ms; 1.71 MP photo 135 / 144 ms; 12 MP 981 / 1,416 ms; 24 MP 2,094 / 2,860 ms at speed 9; speed 10 byte-identical everywhere; speed 8 slower and larger than 9 on the photo (240 ms / 33,739 B vs 135 ms / 22,924 B); speed 7 8–15× slower (2.0 s at 1.7 MP) for 12–24 % smaller files. Decision: fixed speed 9, no effort control.
- Quality is monotonic: 0 inversions over 20 steps (q1…q100) on both sources at speed 9 and at speed 7; q100 is 1.9–5× the source JPEG's bytes (q80 of the 1.7 MP photo: 56,316 B vs 84,376 B JPEG).
- Memory: WASM heap growth 25.9 MB/MP (1.7 MP), 27.4 (12 MP), 27.2 (24 MP) for encode — the heap never shrinks; twenty encodes in one process stay at 60 MB after the first and produce identical bytes (no leak, deterministic). Model: 30 bytes per pixel of heap for the AVIF encode stage on top of the input surfaces; worker recycled after a large AVIF encode.
- Alpha: preserved (sharp hasAlpha true; alpha plane as a second 4:0:0 av1 item; lossy at the same quality — max alpha error 15/255 with the default qualityAlpha, 0 at qualityAlpha 100 for +28 % bytes; fully clear pixels stay 0). Default kept.
- Chroma: the package's default subsample 1 is 4:2:0 (av1C); 4:4:4 costs +4 % bytes here; documented as 4:2:0.
- 10-bit input decodes to 8-bit in the package too (max sample 255 with the default option); native browser decode does the same (probe).
- Animation: sharp cannot write an animated AVIF (pages: 1), so the animated fixture is a brand-rewritten still; the refusal keys on the brand/moov, before any decode.
- WASM decode (not shipped) is 3.4–4.9× slower than libvips and 13.9 MB/MP of heap — one more reason the decoder stays native.
Verdict: PROCEED — decode native, encode @jsquash/avif 2.1.1 at speed 9, lazily, with the AOM notices file; /compress and bulk AVIF output deferred with the reasons in the plan.
